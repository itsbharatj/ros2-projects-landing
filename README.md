# The ROS 2 cheat sheet — landing page

One white screen for readers of the article. They leave their name, best email and ROS 2 experience, tick a box if they want to hear about the free live workshop, and the two-page PDF downloads straight after. Sign-ups are stored in Supabase.

Plain HTML, CSS and JavaScript. No build step, no dependencies. Live at [ros2-projects-landing.vercel.app](https://ros2-projects-landing.vercel.app).

```
index.html               the page and all its copy
styles.css               design (colours and sizes at the top in :root)
app.js                   form validation, the Supabase call, the download
config.js                the only file you need to edit: Supabase keys and your links
vercel.json              caching and security headers for Vercel
assets/
  ros2-cheatsheet.pdf    the sheet (A4 landscape, 2 pages)
  cheatsheet-p1.jpg      previews, generated by cheatsheet/build_sheet.py
  cheatsheet-p2.jpg
  room-map.png           the real occupancy grid of my room, used on the sheet
  bharat.jpg             the small portrait in the header
fonts/                   Fraunces and IBM Plex Mono, subset (SIL Open Font License)
cheatsheet/              the HTML source of the sheet and the script that renders the PDF
supabase/schema.sql      the database: paste into the Supabase SQL editor and run
```

## 1. Supabase (10 minutes)

1. Create a project at [supabase.com](https://supabase.com) (the free plan is plenty).
2. Open the **SQL editor**, paste the whole of `supabase/schema.sql`, run it. It creates the `signups` table, locks it down, and adds the `submit_signup` function the page calls. If you ran the earlier version of this file, it migrates that table in place and keeps its rows. Change the salt string inside the function if you like.
3. **Project settings → API**: copy the **Project URL** and the **anon / publishable** key into `config.js`. Commit, push, done.

Until `config.js` has real keys the form runs in preview mode: it shows the success state, says nothing was saved, and the download still works.

### Why the key in `config.js` is safe

The anon key is meant to be public. With this schema it can do exactly one thing: call `submit_signup()`, which validates every field, drops bots (a hidden honeypot field), allows five submissions an hour per visitor (IP hashed with a salt, never stored in clear), and writes the row with the function owner's rights. Row level security is on with no policies and every table privilege revoked, so the key cannot read, change or delete anything. Keep the **service_role** key out of the site, always.

Reading the data: **Table editor → signups**. The `workshop` column is the tick box; the `workshop_list` view shows only those rows and `signup_counts` the totals. Export CSV from the same screen.

## 2. Your links

In `config.js` fill in `links.article` (the X article URL once it is live) and `links.youtube`. Every link on the page reads from there. Two placeholders are also waiting in the sheet itself, see below.

## 3. Vercel

The project is connected to this repository; every push to `main` redeploys. Nothing to configure: it is a static site served from the repository root, and `vercel.json` adds caching for fonts and assets plus security headers (a Content-Security-Policy that allows scripts, styles and fonts only from this site and network calls only to `*.supabase.co`; if you ever add an inline script or a third-party embed, loosen it there).

To use a custom domain: Vercel → project → Settings → Domains. Then update the URL in the sheet's footer (`cheatsheet/cheatsheet.html`), in the `og:image` tag of `index.html`, and re-render the PDF.

GitHub Pages works too (Settings → Pages → Deploy from a branch → `main`, `/`), it just ignores `vercel.json`.

## Editing the cheat sheet

`cheatsheet/cheatsheet.html` is the sheet. Edit text there, then render the PDF and the previews:

```bash
pip install playwright pillow && playwright install chromium   # once
python3 cheatsheet/build_sheet.py
```

It rewrites `assets/ros2-cheatsheet.pdf` and the two JPG previews, and prints an overflow check per page (negative numbers mean the content fits). One placeholder is waiting in the HTML: `YOUTUBE_URL`, in the Links panel on page 2.

The map in the masthead is the real occupancy grid of my room from Project 2, recovered from the RViz view in the video: the oblique view was rectified with the 1 m grid, classified into free / occupied / unknown at 5 cm cells, and the RViz robot model was replaced by the blue square.

## What is soft about the gate

The PDF is a public file in a public repository, so anyone who knows the path can fetch it without the form. For a free cheat sheet that is the normal trade-off. For a hard gate, move the PDF to a private Supabase Storage bucket and return a short-lived signed URL from an Edge Function after the insert; only the success handler in `app.js` needs to change.
