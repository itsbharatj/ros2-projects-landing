The ideas

Node
One program with one job: camera driver, planner, motor controller. Python: rclpy. C++: rclcpp.
Topic
A named stream. Publishers write, any number of subscribers read, nobody replies: /scan, /cmd_vel.
Service
One request, one reply, like “spawn a turtle at (2, 2)”.
Action
A long task you can watch and cancel: “navigate to this pose”.
Parameter
A node’s settings, changeable while it runs: max_speed, use_sim_time.
Interface
The typed data on the wire: .msg, .srv, .action files. Common ones: table on the right.
Package
A folder of nodes with a package.xml. A workspace holds many packages under src/.
Launch
A .launch.py file starts several nodes with their parameters in one go.
tf2
The tree of coordinate frames, map → odom → base_link → laser. Every reading lives in a frame.
QoS
Delivery settings per topic. Sensors publish best effort; a reliable subscriber then hears nothing.

Workspace build once, source everywhere

ros2_ws/src/my_pkg/
  package.xml        name, dependencies
  setup.py           entry_points → ros2 run
  my_pkg/bumper.py   your nodes
source /opt/ros/jazzy/setup.bash
cd ~/ros2_ws/src
ros2 pkg create --build-type ament_python \
  my_pkg
cd ~/ros2_ws && colcon build --symlink-install
source install/setup.bash

Build from the workspace root, not inside src. Put both source lines in ~/.bashrc.

One complete node subscribe, decide, publish

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist
from sensor_msgs.msg import LaserScan

class Bumper(Node):
    def __init__(self):
        super().__init__('bumper')
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.create_subscription(LaserScan, '/scan',
                                 self.on_scan, 10)
        self.create_timer(0.1, self.tick)     # 10 Hz
        self.ahead = 9.9

    def on_scan(self, msg):
        self.ahead = min(r for r in msg.ranges if r > 0.05)

    def tick(self):
        cmd = Twist()
        if self.ahead > 0.5:
            cmd.linear.x = 0.2    # m/s, forward
        else:
            cmd.angular.z = 0.6   # rad/s, turn left
        self.pub.publish(cmd)

def main():
    rclpy.init()
    rclpy.spin(Bumper())
    rclpy.shutdown()

What it does. Drives forward until the LiDAR sees something within half a metre, then turns left until the way is clear.

The three parts of almost every node: a publisher that sends Twist commands, a subscriber whose callback runs on each LaserScan, and a timer that decides ten times a second. spin() keeps them running.

Run it. Save as my_pkg/bumper.py, add 'bumper = my_pkg.bumper:main' under console_scripts in setup.py, build, then ros2 run my_pkg bumper.

Moving a robot the /cmd_vel topic

linear.xforward speed in m/s; 0.2 is a safe start angular.zturning speed in rad/s, positive turns left; try 0.5

ros2 run teleop_twist_keyboard teleop_twist_keyboard drives anything that listens on /cmd_vel:

uiojklm,.

i forward, , back, j and l turn on the spot, corners drive in arcs, k or any other key stops. q/z change both speeds by 10%, w/x linear only, e/c angular only.

Teleop a real robot

Drive a wheeled robot from your laptop over /cmd_vel. Run nodes across several terminals and watch the sensors in RViz.

Map a room

SLAM builds an occupancy grid while you drive. Save it, give Nav2 a goal in RViz, and the robot plans a path and drives around whatever is in the way.

slam_toolbox, map_saver_cli, nav2_bringup
3

Frontier exploration

Your own node. Frontiers are free cells next to unknown ones: cluster them, score by size and distance, send the best to Nav2, repeat until none remain.

OccupancyGrid, NavigateToPose, a coding agent
4

Semantic navigation

Capture images while exploring, let a vision-language model label them, store labels with poses in a vector database. “Go to the couch” finds the nearest match.

a VLM, Chroma, Nav2
5

Talk to the robot

The ROS-MCP server exposes topics, services and actions as tools. Claude Code or Codex reads the sensors, plans, and drives from plain English.

ros-mcp-server, rosbridge_server
6

A robot arm

Build the $200 SO-101, wrap it in ROS 2, let MoveIt do the inverse kinematics. Record trajectories with the leader arm, replay them by hand or by LLM.

LeRobot, ros2_control, MoveIt 2

When nothing works

  1. Did this terminal source the workspace? source install/setup.bash, then ros2 pkg list | grep my_pkg.
  2. Is the node running, and is the topic name exactly right? ros2 node list, ros2 topic list. Mind slashes and namespaces.
  3. echo shows nothing although a publisher exists: QoS. Check ros2 topic info -v, then ros2 topic echo --qos-reliability best_effort /scan.
  4. Two machines cannot see each other: same ROS_DOMAIN_ID, same network, multicast allowed. Test with ros2 multicast send / receive.
  5. The robot ignores you: ros2 topic echo /cmd_vel. If commands arrive, check the motor enable, the e-stop and the robot’s real topic name.
  6. In simulation every node needs use_sim_time:=true, or tf and Nav2 complain about time.
  7. Build fails: colcon build --packages-select my_pkg --event-handlers console_direct+ shows the real error. Missing dependency: rosdep install --from-paths src --ignore-src -y.
  8. Still stuck: ros2 doctor --report, then search the exact error on Robotics Stack Exchange.

Hardware that works

A Raspberry Pi 5 or Jetson Orin Nano Super as the brain, a Slamtec RPLIDAR C1 for mapping, a TurtleBot3 Burger or Waveshare UGV Rover (both ship with ROS 2 packages), the SO-101 arm for manipulation. Ubuntu 24.04 on x86 is easiest; on a Mac, Ubuntu inside UTM (mac.getutm.app) runs all but heavy Gazebo scenes.
