02 · FoundationsThe ROS 2 Cheatsheet

What ROS 2 is, and when you need it.

ROS, the Robot Operating System, is by far the most widely used tool in robotics. NASA picked ROS 2 for the ground software of its VIPER Moon rover. And all you need to start is a laptop.

The problem it solves

Picture a self-driving car: LiDAR and cameras to see, a computer to decide, motors to steer, accelerate and brake.

Every sensor speaks at its own rate and in its own format. A LiDAR produces hundreds of thousands of 3D points a second; a camera sends around 30 images a second. All of it has to be processed in parallel and turned into commands.

Without ROS you would write a whole messaging system before a single line of driving logic. And if it all lives in one giant program, one bug in the camera code takes everything down.

ROS is the reliable communication layer between all the parts of your robot, so you can work on higher-level logic instead of plumbing.

Learn ROS 2, not ROS 1

ROS 1 reached end of life in May 2025. ROS 2 is the version to learn today.

Use ROS 2 when

  • Your robot has several sensors and motors
  • You need simulation before touching hardware
  • You want ready-made navigation (Nav2) or arm planning (MoveIt)
  • Several programs must share data in real time

Skip it when

  • The project is simple, like a line-following robot
  • An Arduino sketch can do the whole job
  • There is one sensor, one motor and no simulation

03 · Core conceptsThe ROS 2 Cheatsheet

Nodes talk in three ways.

Each program in ROS 2 is a node, and each node does one job. In the car, the LiDAR processor, camera processor, obstacle detection, planning and control are all separate nodes.

PatternUse it forCar exampleInspect it
TopicContinuous streams of dataLiDAR points on /lidar, images on /cameraros2 topic echo /lidar
ServiceQuick, one-off questionsPlanner asks the map node for the speed limitros2 service call …
ActionLong tasks that report progress“Park the car”, with updates until it's doneros2 action send_goal …

Messages

The typed data a topic carries, e.g. geometry_msgs/Twist for velocity. See any type with ros2 interface show.

Parameters

Per-node settings you can change without recompiling, like a max speed. ros2 param list

Launch files

Start many nodes with their settings in one command: ros2 launch pkg file.launch.py

04 · Code layoutThe ROS 2 Cheatsheet

Packages and workspaces.

All ROS 2 code is organised and shared as packages. A workspace holds many packages, each in its own folder under src/.

A Python package

my_package/
  package.xml          # name + dependencies
  resource/my_package
  setup.cfg
  setup.py             # entry points for nodes
  my_package/          # your node .py files

A workspace

workspace_folder/
  src/
    cpp_package_1/
      CMakeLists.txt
      include/cpp_package_1/
      package.xml
      src/
    py_package_1/
      package.xml
      resource/py_package_1
      setup.cfg
      setup.py
      py_package_1/
  build/  install/  log/  # made by colcon

Create, build, run

# 1. make a workspace
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src

# 2. create a package
ros2 pkg create my_package \
  --build-type ament_python \
  --dependencies rclpy

# 3. install dependencies
cd ~/ros2_ws
rosdep install --from-paths src \
  --ignore-src -y

# 4. build (from the workspace root)
colcon build --symlink-install

# 5. load it into this terminal
source install/setup.bash

# 6. run a node
ros2 run my_package my_node
The #1 beginner error: “Package not found”. Open a new terminal? Run source install/setup.bash again. Add the ROS line to ~/.bashrc so you never forget:
source /opt/ros/<distro>/setup.bash

Build only what changed

colcon build --packages-select my_package

05 · CommandsThe ROS 2 Cheatsheet

The CLI you'll actually use.

For quick debugging and inspection. Keep this page open in a second window.

Run things
ros2 run my_car lidar_nodeStart one node
ros2 launch my_car car.launch.pyStart several nodes at once
ros2 pkg listInstalled packages
ros2 pkg executables my_carNodes inside a package
Nodes
ros2 node listRunning nodes
ros2 node info /lidar_nodeIts topics, services, actions
Topics
ros2 topic list -tAll topics, with types
ros2 topic echo /lidarPrint messages as they arrive
ros2 topic hz /cameraHow often messages arrive
ros2 topic info /cmd_vel -vWho publishes / subscribes
ros2 topic pub --once /cmd_vel \
  geometry_msgs/msg/Twist \
  "{linear: {x: 0.2}}"		Publish by hand
Services, actions, params
ros2 service list -tAll services
ros2 service call /srv type "{...}"Ask a question
ros2 action list -tAll actions
ros2 action send_goal /a type "{...}" -fSend a goal, see feedback
ros2 param listAll parameters
ros2 param set /node name valueChange one live
Types and recording
ros2 interface show <type>Fields of a message
ros2 bag record -aRecord every topic
ros2 bag play <folder>Replay a recording
Look at it
rviz23D view of what the robot sees
rqt_graphLive map of nodes and topics
ros2 doctorCheck your setup
Stuck? Tab-complete everything. ros2 topic <Tab><Tab> lists every option, and -h works on every command.

06 · Tools and setupThe ROS 2 Cheatsheet

Tools, hardware and setup.

Five tools do most of the heavy lifting. Hardware is optional: everything in this guide can start in simulation.

RViz

See what the robot sees

LiDAR points, camera images, maps and paths in 3D.

rqt_graph

See how nodes connect

A live map of nodes and topics, so you can spot a missing link.

Gazebo

Test in a virtual world

A simulator for your robot before you use real hardware.

Nav2

Drive from A to B

A ready-made navigation system that moves a mobile robot while avoiding obstacles.

MoveIt

Move an arm safely

The Nav2 of robot arms: plans movements that don't hit anything, and does the inverse kinematics for you.

SLAM Toolbox

Build a map

Turns LiDAR scans into a map while the robot drives. Cartographer is the alternative.

Hardware (or use simulation)

ComputerRPi or Jetson Orin Nano on the robot
SensorA 2D LiDAR
RobotTurtleBot3, a ROS 2-supported AMR such as Waveshare's UGV Rover, or build your own
ArmSO-101: about $200 to build, free in simulation
OSUbuntu, ideally on x86. On a Mac, VMs also work well

Install checklist

  • Install Ubuntu (native, dual boot or a VM)
  • Install the ROS 2 distro that matches your Ubuntu version from docs.ros.org. Pick an LTS release
  • Add source /opt/ros/<distro>/setup.bash to ~/.bashrc
  • Install colcon and rosdep
  • Run ros2 run turtlesim turtlesim_node. If a turtle appears, you're ready
Same network, robots not showing up? Make sure every machine uses the same ROS_DOMAIN_ID.

08 · Projects 0–2The ROS 2 Cheatsheet

Move, teleop, map.

The fundamentals. Do these in simulation if you don't have a robot yet.

00 · Turtlesim

# terminal 1: a blue window with a turtle
ros2 run turtlesim turtlesim_node
# terminal 2: drive it with the arrow keys
ros2 run turtlesim turtle_teleop_key
# terminal 3: watch the velocity commands flow
ros2 topic echo /turtle1/cmd_vel

Before you press a key, nothing is published on cmd_vel. That's why the turtle sits still.

01 · Teleoperate a real robot

# start keyboard teleop
ros2 run teleop_twist_keyboard \
  teleop_twist_keyboard

# in another terminal
ros2 topic echo /cmd_vel

The keys i j k l map to linear and angular velocities. Teleop publishes them to /cmd_vel and the robot's driver turns them into wheel speeds.

Your robot may use a different node or package name, so check its docs.

02 · Map a room with SLAM, then navigate

# 1. bring up robot + LiDAR
# 2. start mapping
ros2 launch slam_toolbox \
  online_async_launch.py
# 3. drive with teleop, watch RViz
# 4. save the map
ros2 run nav2_map_server \
  map_saver_cli -f my_room
# 5. navigate on it
ros2 launch nav2_bringup bringup_launch.py \
  map:=my_room.yaml
  • Drive slowly while mapping. Fast turns blur the map
  • In RViz, use 2D Pose Estimate to tell Nav2 where the robot is
  • Then click Nav2 Goal and the robot plans a path and drives there
  • Put a box in its way and watch it re-plan

09 · Projects 3–6The ROS 2 Cheatsheet

Explore, see, talk, grasp.

From here you stop only using ROS 2 tools and start building your own on top of them, with a coding agent writing the code.

03 · Frontier exploration

The robot maps the room itself

Frontiers are the edges between mapped and unexplored space. The loop:

  1. Find frontier cells on the map
  2. Group and sort them
  3. Pick one as a goal and send it to Nav2
  4. Repeat until no frontiers are left

It works like a robot vacuum mapping a new house. Describe the goal and constraints to Codex or Claude Code, then test and fix iteratively.

04 · Semantic navigation

“Go to the door”

An occupancy grid only knows free, occupied and unknown. To add meaning:

  1. Capture images at regular intervals while exploring
  2. A VLM labels objects and places
  3. Store labels and coordinates in a vector database
  4. Match a query by meaning and send the best coordinates to Nav2

Matching by meaning means “couch” still finds “sofa”.

05 · LLM-controlled robot

Talk to your robot

An MCP server bridges ROS 2 and an LLM client, so the model can read sensors and send commands. Connect the open-source ROS-MCP server to Claude, then try:

  • “What topics are available?”
  • “What's the message type of /cmd_vel?”
  • “Make a complete circle.”
  • “Survey the room.” (a long-horizon task)
06 · SO-101 arm + MoveIt

A factory arm on your desk

  1. Assemble the arm (allow 4–6 hours) or set up simulation
  2. Calibrate leader and follower, get teleop working (LeLab gives you a GUI)
  3. Build the ROS 2 package and connect MoveIt
  4. Record trajectories, name them, and replay them yourself or through an LLM

By default the SO-101 runs LeRobot. ROS 2 adds deterministic control and MoveIt's IK and planning.

10 · Keep goingThe ROS 2 Cheatsheet

Learn on demand.

You don't need months of courses, advanced math or years of programming first. Start on real projects from day one, get your hands dirty, and fill in the gaps as you go.

My AI workflow

  • Write down what the robot must do and its constraints first
  • Let a coding agent (Codex, Claude Code) write the code, ideally inside a harness
  • Run it, then feed back the exact errors and ros2 topic echo output
  • Iterate on small steps: one node, one behaviour at a time

When it doesn't work

  • Did you source install/setup.bash?
  • Is the node running? ros2 node list
  • Is data flowing? ros2 topic hz /topic
  • Are names and types right? rqt_graph, ros2 topic info -v
  • Using two machines? Same ROS_DOMAIN_ID
